# 衣物处理等待体验实施计划

## 已确定的体验

目标是让 1–2 分钟的等待可理解、可离开、有可选消遣。单件和多件共用站内任务提示，完成后由用户点击核对，不自动跳转或入柜。

- 展示真实阶段、已等待时间；生成过程不显示虚构百分比或保证完成的倒计时。
- 全局任务入口持续可用；任务完成提示一次，结果入口保留。失败、未知状态使用准确文案，不自动重试模型。
- 衣物进入处理后主动弹出一次居中小提示，直接提供聊天、翻牌、逛衣柜和留在这里看进度。右上角仅作任务查询入口；关闭提示或重复轮询不再弹出，重新提交处理可再次提示。
- 用户点击“和鱼搭助手聊聊”才打开助手；话题仅预填，手动发送，使用现有聊天额度及图片授权。
- 用户点击“衣物记忆翻牌”才打开 Ant Design Vue 弹层。8 张本地衣物插画、4 对，无倒计时；显示配对数、翻牌次数，可再玩一局。
- 完成提示在游戏和手机助手内也可见，不关闭活动。关闭游戏保留本轮，刷新重开；不添加排行榜、奖励或额外 AI 调用。
- 网站打开时提供站内提醒；重新进入可找回待核对结果。尊重已有音效开关、减少动态效果偏好和手机尺寸。

2026-10-04 用户要求“写计划文档到项目中，然后开始实现”，本次按该授权直接实现以上确认的方向。

## 实现安排

1. 添加全局 Pinia 任务监测，由主布局启停。使用已有单件、批次 API，发现任务后按 ID 跟踪；批次子任务去重，按真实调用与目标状态判断完成，账号切换清理状态。
2. 主布局添加处理开始的小提示、站内任务汇总弹层及一次完成提醒，待核对项保持可访问。处理开始提示居中自动出现，聊天和游戏仍由用户点击打开。网络失败保留已知状态，提示稍后更新；页面隐藏暂停轮询，回到前台立即同步。
3. 单件、多件等待区添加可复用活动入口。助手通过事件打开并可选预填话题；不自动发消息或授权图片。游戏挂在主布局以保留当前局。
4. 多件等待区补充已等待时间和已完成件数；现有单件步骤沿用。所有新增控件使用 Ant Design Vue，配色复用主题。
5. 从相邻前端源码执行 `npm run build:server` 发布，禁止修改压缩产物。确认实际运行服务提供新资源。

## 接口与边界

- 复用 `/api/closet/tasks`、`/api/workflows/{id}`、`/api/closet/batches` 和批次详情；不修改后端数据结构、数据库或处理管线。
- 新增前端任务观察状态、助手打开事件和游戏打开事件；单件/批次开始后及时注册任务，防止短任务在首次发现前完成。
- 批次不能只凭 `NEEDS_REVIEW` 判断完成，必须等待调用与衣物子任务都结束；不把 `metrics.generated` 当成功数。
- 处理完成仍需核对，取消与失败不展示“已整理好”；首次进入不把旧历史批量弹成新通知。

## 验证与验收

- 类型检查与生产发布构建通过。
- 浏览器验证单件、多件、处理中切换路由、成功/失败/未知/取消、多任务去重和断网恢复。
- 验证进入处理主动弹出小提示，关闭后轮询/刷新不重复弹出；聊天/游戏按钮确实打开对应功能，重做后可重新提示。
- 验证翻牌配对、不匹配回盖、关闭重开保留、再玩一局、完成提醒不打断游戏。
- 验证助手入口打开但不发送，用户草稿不被覆盖，手机全屏助手仍可查看任务提示。
- 检查桌面、390px 手机、浅深主题、键盘操作、减少动态效果及无横向溢出；使用受控接口响应验证状态切换，不触发付费 AI。
