# 衣物批次录入与合图试验 v1（历史方案）

> 本文保留2026-10-02初始设计，部分默认通道、界面与格位规则已被更新。当前行为以[衣物入库最新完整设计](衣物入库最新设计.md)为准，勿将本文直接作为实现契约。

实施日期：2026-10-02。合图是显式试验选项，默认逐件生成。现有自拍、相机入口、透明处理、贴纸和逐件确认继续复用。

## 用户操作

添加衣物默认进入批次录入。默认单件通道、智能自动。单件通道每张照片选一个主目标，可以选择最多10张单件照；多件通道每张照片识别最多10个目标，可用于同框衣物或穿着照。

智能自动在服务端执行 `visibleFraction >= 0.8 && keyDetailsVisible`，不是置信度，也不是框面积。未达标候选仍显示原因，不生成。全自动允许补全所有可辨目标；手动模式先上传，再在校正方向后的预览中点击指定目标，单件通道每照片只保留一个标记，多件最多10个标记。标记不在可辨衣物上时不猜测。补全件在批次页、衣物详情中提示推测，不能把隐藏细节当作真实信息。

逐件查看来源原照片和结果，再沿用原有核对入柜。批次记录恢复已保存照片、目标和进度；未上传的本地选择需重新选择。单件重做只增加一个生成调用，沿用目标与识别信息。已保存整图但本地导入失败时，可继续本地拆分导入，不重复请求模型；已导入任务的透明/贴纸异常沿用详情页修复。

## 图片管理

每张原图最多50MiB、6400万像素，宽高32到16384，仅JPEG/PNG。先读图片头验证尺寸，然后采样解码并应用EXIF方向。原件字节与SHA256保留；预览/识别副本最长边不超过1600。传统单件工作流的输入也采样到2048，并保留独立原件。HEIC明确提示转换，浏览器或相机导出的JPEG可直接上传。

批次生成参考从原图采样后按目标归一化框裁切，保留2.5%上下文，再放入编号格位；每格参考1024或1600。穿着照不提前去背景。输出横向等宽1/2/3格，编号仅用于输入，输出不得包含编号；整图固定1024×1024，或每件约1024×1024。实际输出尺寸不符即停止拆分并保留整图，不悄悄重新请求。

## 接口与持久化

- `POST /api/closet/batches`：multipart `options`（JSON通道/策略）和`file`；`Idempotency-Key`为UUID。
- `POST /api/closet/batches/{id}/sources`：追加原件，同一上传编号相同内容幂等；开始识别后不可追加。
- `POST /api/closet/batches/{id}/recognize`：`markers/provider/model`。每来源照片一次识别；手动模式无标记的照片本地跳过。
- `POST /api/closet/batches/{id}/generate`：`targetIds/groupSize/referenceSide/sizePolicy/provider/model/quality`。剩余实际目标决定格数。
- `POST /api/closet/batches/{id}/calls/{callId}/resume-local`：仅继续已保存整图的拆分导入。
- `GET /api/closet/batches`、`GET /api/closet/batches/{id}`：记录和进度。
- `GET /api/closet/batches/garments/{garmentId}/source`：当前账号的原件溯源。

V9迁移新增批次和调用记录。上传、目标、参考图、输出格位、衣物及本地工作流有稳定编号。来源原件校验哈希，文件查询校验归属。调用保存冻结模型、供应商修订、提示词、参数和schema，历史不重新准备配置或自动重跑。重启时RUNNING调用标为UNKNOWN，QUEUED继续；网络超时/5xx等不自动重发。失败保留其他调用、已完成衣物和已返回整图。

旧单件接口保持响应兼容并共用图片采样、原图保留、云端额度及既有本地后处理。它仍使用旧版单目标识别schema；新三种策略从批次接口进入，旧任务配置不改写。

## 额度与费用

每日20单位。每个云端识别、每次生成（含返工）分别1单位；传统“识别+整理”2单位。上传/查询/本地处理0。批次提交在同一事务锁定账号额度、创建所有调用，额度不足全部拒绝；重复编号不重复预留。保留首次GENERATE与REWORK类别。

费用按用户确认的OpenAI 1:1标准价。2026-10-02核对官方[价格](https://developers.openai.com/api/docs/pricing)及[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)：flare每百万图像输入8美元、文字输入5美元、图像输出30美元；Luna输入0.10、缓存输入0.01、输出0.50美元。输入超过272K按官方长上下文系数。只对明确支持的模型且用量字段齐全计算；缺少缓存/图像文字拆分或未知模型显示“金额未知”。这些是调用用量换算，不是支付凭证，价格需随模型重新核对。

## 试验与准入

独立测试环境、隔离测试账号与存储，预算目标5美元，每次追加前核对完整用量与累计金额，接近预算保留余量停止；金额不明停止扩展。模式和实际目标固定，重复使用识别结果，比较逐件与合图。

矩阵：1/2/3件，固定整图与单件分辨率，1024/1600参考；两张不同衣物完整/一件不完整/两件不完整，分别智能与全自动。记录上传、识别、跳过、生成、视觉采纳数量、失败与返工、等待、每件采纳成本。颜色/图案/文字/结构/格位对应逐项人工核对，补全与完整件分别评价。最终用户采纳需要实际逐件确认，不用模型自评代替。

只有保真通过且包含失败与返工的每件采纳成本下降至少20%，用户才决定启用对应模型默认配置。切换模型重新验证。本轮真实结果见[报告](../reports/2026-10-02-batch-experiment.md)，不能用自动化mock结果代替真实保真验收。
