# 全身穿搭与呈现增强设计（2026-10-09）

**状态：已确认，第 0、1、2 期已在本分支实施（`feat/outfit-fullbody`，基于 `feat/outfit-recommend-p4`）；第 3、4 期只做数据准备，不接入功能。** 决策记录 D42~D50，接续[推荐引擎总设计](2026-10-08-智能搭配推荐引擎与语义召回设计.md)。采集操作规范见 [整套穿搭样本采集规范](../OOTD_SAMPLE_COLLECTION.md)。

## 一、背景与目标

看了大量 OOTD 之后的结论：一套穿搭的"好看"是整个人一起成立的，不只是衣服。除了上装、下装、鞋，还有帽子、头饰、袜子、包、手里拿的东西（玩偶、伞、相机……），以及姿势、发型、表情、构图。

当前引擎的局限（实测）：

| 问题 | 现状 |
|---|---|
| 分类错误 | 裤袜/连裤袜被当成**下装**（名称含"裤"）；小黑裙、礼服裙被当成下装；洛丽塔 OP/SK/JSK、水手服套装、发箍、发夹、头饰都是"品类不明"，不参与推荐 |
| 缺组合类型 | 只有"上装+下装"和"连衣裙单穿"两种主体。背带裙、JSK、背带裤这类"一体但要内搭"的单品无法组合 |
| 配件不参与 | 推荐只出上装、下装、连衣裙、鞋和外套建议。袜子、头饰、帽子、包、手持物从不出现 |
| 审美来源单一 | 模板库是人工整理的 66 条，没有从真实整套穿搭中学习的渠道 |

目标：

1. 修正分类，补上"一体裙+内搭"、头饰、手持物。
2. 推荐结果附带配件建议（袜子、头饰、帽子、包、手持物、围巾），穿裙子偏冷时提示加裤袜。
3. 建立"整套穿搭图 → 多模态提取 → 人工审核 → 统计与模板草稿"的采集工具，让审美可以从真实穿搭中持续积累，并保持白盒：学到的东西最终都落成**可读、可审核的模板和规则**，不训练黑盒模型。
4. 提取时一次记全（物品、姿势、发型、表情、构图、场景），使用分期接入。

非目标：

- 不训练神经网络，不做端到端"看图打分"。
- 本期不把姿势、发型、表情接入提示卡片和生图（第 3、4 期）。
- 不保存原图、人脸、身份、年龄、身材数据。

## 二、两层模型（D42）

| 层 | 内容 | 用途 | 是否参与搭配打分 |
|---|---|---|---|
| **物品层** | 衣物；帽子、头饰；袜子/裤袜；包；手持物；围巾、眼镜、首饰、腰带、手套 | 推荐引擎：组合、配件建议、模板 | 主体与鞋参与打分；配件只做建议，不改总分 |
| **呈现层** | 姿势、手部动作、拍摄角度与构图、场景、发型、表情 | 提示卡片、OOTD 生图提示词 | 否 |

两层分开，推荐引擎的白盒打分不因为加入姿势、表情而变成黑盒；呈现层可以独立增长。

## 三、物品层：角色与分类（D43）

### 3.1 新增角色

| 角色 | 中文 | 典型品类 | 规则 |
|---|---|---|---|
| `OVERALL` | 一体裙/背带（需内搭） | 背带裙、背带裤、JSK、吊带裤、jumper skirt、pinafore、overalls | 必须与一件上装同时出现；不能与下装或连衣裙同时出现。例外（2026-10-10 用户反馈）：名称或品类含“围裙”的围裙式背带裙/背带裤遮住前胸后背，按 `ONE_PIECE` 单穿，不配上衣（`OutfitRules.markWornAlone`，字段 `_wearRole=ALONE`） |
| `HEADWEAR` | 头饰 | 发箍、发夹、发卡、发带、头花、发饰、头纱、抓夹、KC | 一套最多一件；只做建议 |
| `HANDHELD` | 手持物 | 玩偶、公仔、毛绒挂件、雨伞/阳伞、扇子、相机、拍立得、花束 | 一套最多一件；只做建议，且只在风格或用户描述相关时出现 |

原有 `SOCKS` 扩展为"袜子/裤袜"，包含裤袜、连裤袜、丝袜、打底袜、过膝袜、长筒袜、中筒袜、短袜、袜套、腿套。

### 3.2 分类修正（按顺序匹配，先到先得）

1. **袜** → `SOCKS`（放在最前，避免"裤袜""连裤袜"被"裤"匹配成下装）
2. **头饰词** → `HEADWEAR`
3. **背带裙/背带裤/JSK/吊带裤/pinafore/overalls** → `OVERALL`
4. **连衣裙/背心裙/吊带裙/连体/连身/小黑裙/礼服/婚纱/旗袍/晚装/套装/OP** → `ONE_PIECE`（"套装"指整套入柜的一件物品，如水手服套装、西装套装；它已构成完整主体）
5. **马甲/材质背心**（马甲、牛仔背心、针织/毛衣/西装/羽绒/皮/工装背心、waistcoat、gilet）→ `OUTER`（2026-10-09 内测修复：马甲穿在上衣外面，不能当背带裙/背带裤的内搭；只写"背心"仍按无袖上衣 `TOP`；"马甲裙"与"背心裙"同为 `ONE_PIECE`）。外套建议不会把马甲放在背带裙/背带裤外面，主体是牛仔时牛仔外层排后
6. 外层、下装（含 **SK**）、上装、鞋、帽、包，与原来相同
7. **手持物词** → `HANDHELD`（放在下装、上装、鞋、包之后，避免"伞裙""娃娃领""娃娃鞋""手拿包"被误判）
8. 首饰类 → `ACCESSORY`

`OP`、`SK`、`JSK`、`KC` 只在前后不是英文字母时匹配（`JSK` 不会被当成 `SK`）。修正前后见第十节测试表。

前端拼图角色（搭台）不新增：`OVERALL` 显示为"连体"位置并压在上装之上，`HEADWEAR` 放在帽子位置，`HANDHELD`、`SOCKS` 放在配饰位置。搭台已保存的数据结构不变。

### 3.3 一体裙 + 内搭（D44）

主体组合从两种扩展为三种：

| 主体 | 组成 |
|---|---|
| 分体 | 上装 + 下装 |
| 连衣 | 连衣裙/连体衣/套装（单穿） |
| **一体+内搭** | 上装 + 一体裙/背带（`OVERALL`） |

- 召回：`OVERALL` 每次取前 6 件。
- 结构规则：`OVERALL` 必须有上装；不能有下装或连衣裙；最多一件。
- 打分：配色"上下"关系中，一体裙按"下装"参与（它占据了视觉上的下半身与胸前一块）；外套建议照旧。
- 今日灵感补全：模板只给了一体裙时，自动补一件上装。

## 四、配件建议（D45）

沿用外套的做法（D7）：**配件建议放在搭配旁边，不进入组合、不改总分**。这样不会出现"因为有个发箍，这套分数变高了"的不可解释情况。

每套搭配最多 3 条建议，每个角色最多 1 件，按下面的白盒分数从高到低取，低于门槛不出：

| 因素 | 分数 |
|---|---|
| 基础 | 0.3 |
| 风格与这套搭配（或用户想要的风格）重合 | +0.3 |
| 颜色：中性色，或与身上某件同色系，或呼应身上的辅色 | +0.2 |
| 季节标签匹配 / 不匹配 | +0.1 / −0.3 |
| 正式程度相差 ≤1 | +0.1 |
| 你常选（正反馈） / 冷却中或避开的颜色 | +0.1 / 不出现 |
| 用户描述里点到（如"带上小熊""戴发箍"） | +0.5 |

门槛 0.5。各角色的额外条件：

| 角色 | 条件 |
|---|---|
| 袜子/裤袜 | 只在腿部露出时（半身裙、连衣裙、一体裙、短裤）。**气温 < 15°C**（未知温度时按秋冬）优先裤袜类并说明"穿裙子 X°C 偏凉"；**≥ 22°C** 时裤袜类不出。冷且衣柜里没有裤袜时，在这套的提示里写"可以加一条裤袜（衣柜里还没有）" |
| 头饰 | 必须风格重合或被点到（避免每套都配发箍） |
| 手持物 | 必须风格重合或被点到 |
| 帽子 | 季节匹配；毛线帽/针织帽只在冷天 |
| 包 | 正式程度相近 |
| 围巾 | 只在 < 12°C |

用户指定的配件（"今天戴这个发箍"）仍按原逻辑进入组合本身。

## 五、模板：配件槽位与风格分组（D46）

- 模板槽位本来就按角色定义，新增角色可以直接用（`OVERALL`、`HEADWEAR`、`SOCKS`、`HANDHELD`）。
- 带配件槽位的模板：今日灵感会要求用户有对应配件，缺一件时给"差一个白色过膝袜就能穿……"的提示；常规推荐只在组合里确实包含这些配件（用户指定）时命中。
- 本期新增 8 条草稿模板（全部待审核），覆盖一体裙+内搭、JK、洛丽塔、冬季裙装+裤袜、小黑裙。洛丽塔、JK 这类有严格约定的风格**只放进模板**，不改通用规则。
- 样本生成的模板草稿（第六节）存数据库，与资源文件模板一起出现在 `/admin/templates`，同样默认"待审核"。

## 六、整套穿搭样本采集（D47、D48）

### 6.1 流程

```
管理员上传整套穿搭图（附来源与许可）
  → 去重（图片 SHA-256）
  → 多模态模型一次提取（结构见 6.3）
  → 自动拒收（多人、拼图、明显未成年、非照片……）→ 立即删除原图
  → 人工审核：核对/修改提取结果 → 通过 或 拒绝
  → 审核完成即删除原图，只保留结构化结果与来源链接
  → 用途：① 统计（角色、配件、品类组合、配色组合、风格、姿势……）
          ② 一键生成模板草稿 → /admin/templates 审核 → 参与推荐
          ③ "其他"类物品汇总 → 词表升级候选
          ④ 姿势、发型、表情、构图库（第 3、4 期使用）
```

### 6.2 采集原则（摘要，全文见采集规范）

- 一张图一个人、一套衣服；尽量全身（至少上装、下装、鞋）；正常光线、少滤镜。
- 收日常可穿的搭配；秀场、cosplay、演出服、制服不收（JK/洛丽塔作为日常风格可以收，但排除明显未成年人）。
- 来源混合（街拍、品牌型录、普通人分享），季节、场合、人群、主色尽量均衡；同一套多角度只算一套。
- 记录来源链接、许可、发布日期；商用前核实许可。
- 先收 300~500 套高质量样本。

### 6.3 提取结构（`ootd-v1`）

一次调用、一次记全。字段都允许"看不清/UNKNOWN"，不许猜：

```jsonc
{
  "usable": true,                       // 是否可用
  "rejectReason": "NONE",               // NONE/MULTIPLE_PEOPLE/NOT_FULL_OUTFIT/COLLAGE/MINOR_LIKELY/NOT_PHOTO/HEAVY_EDIT/OTHER
  "presentation": "FEMININE",           // 穿搭呈现：FEMININE/MASCULINE/NEUTRAL/UNKNOWN（不是对人的性别判断）
  "seasons": ["秋"],  "occasions": ["日常"],  "styles": ["甜美", "学院"],
  "items": [{
    "role": "OVERALL",                  // 与引擎角色一致（含 HEADWEAR/HANDHELD/OVERALL/SOCKS…；认不出用 OTHER）
    "category": "JSK",                  // 中文品类名，示例词不是限制
    "primaryColor": "藏蓝色", "secondaryColors": ["白色"], "patterns": ["格纹"],
    "fit": "合体", "length": "中长款",
    "wear": "NA",                       // 上装：TUCKED/HALF_TUCKED/UNTUCKED；外套：OPEN/CLOSED；其他 NA
    "visibility": "FULL",               // FULL/PARTIAL（被挡或裁切）
    "confidence": "HIGH",               // HIGH/MEDIUM/LOW
    "description": "方领格纹背心裙，胸前有蝴蝶结"
  }],
  "pose": { "stance": "STANDING", "bodyAngle": "THREE_QUARTER", "gaze": "AWAY",
            "hands": "一手提包，一手自然下垂", "description": "重心在后脚，微侧身",
            "tendency": "FEMININE" },   // 姿势常见于哪种呈现，软标签
  "framing": { "shot": "FULL_BODY", "cameraAngle": "EYE_LEVEL", "mirrorSelfie": false },
  "scene": { "setting": "STREET", "description": "秋天街边，落叶" },
  "hair": { "length": "LONG", "description": "低双马尾" },
  "expression": "SMILE",                // SMILE/NEUTRAL/COOL/PLAYFUL/HIDDEN/UNKNOWN
  "highlights": "格纹 JSK 配白衬衫与白色过膝袜，经典学院感"   // 只做模板文案草稿，不作为"好看"的依据
}
```

**不提取**：脸部特征、身份、年龄、身高体重、身材数据、文身等可识别特征。

**"好看"的标签来自管理员挑图与审核，不来自模型打分**（D48）。

### 6.4 自动拒收与隐私

- `rejectReason` 为 `MINOR_LIKELY`、`MULTIPLE_PEOPLE`、`COLLAGE`、`NOT_PHOTO` 时直接拒收，原图立即删除，只保留拒收原因与来源链接（便于避免重复收）。
- 原图只保存到审核完成；通过或拒绝时删除。数据库不存图片内容。
- 结构化结果不含可识别个人的信息。
- 每次提取记入 `model_usage`（功能 `OOTD_EXTRACT`），只记 token 数。

### 6.5 样本 → 模板草稿（D49）

从一条已通过的样本生成：

- 槽位：主体（上装/下装/连衣裙/一体裙）+ 鞋 + 有明确颜色的配件（头饰、袜子、帽子、包）；手持物、首饰不进槽位（太个人化）。
- 每个槽位：角色 + 品类关键词 + 颜色系；花纹样本为纯色时限制"花纹 ≤ 0"，有花纹时要求"至少有花纹"。
- 人群按 `presentation`（中性/未知不限），季节、场合来自样本；类型由管理员选"经典/流行"，流行默认有效期 6 个月。
- 文案用 `highlights`，管理员可改。
- 生成后进入 `/admin/templates`，默认"待审核"，参考信息写"来自样本 xxx（来源链接）"。

### 6.6 统计（只统计已通过样本）

角色出现率、配件出现率、主体品类组合 Top、上下装颜色系组合 Top、风格分布、季节/场合分布、姿势（站姿/朝向/视线）分布、"其他"类物品描述汇总（词表升级候选）。按穿搭呈现分组查看，避免一类人群的偏好被平均掉。

CREATE TABLE ootd_sample (id, status, source_url, license, note, image_sha256 UNIQUE, image_path,
  extractor_version, model, extraction_json, reviewed_json, reject_reason, presentation,

## 十一、实现要点

- 提取复用识图服务商与模型（`RecognitionService.prepareCustom`），独立的提示词 `resources/ootd/ootd-v1.txt` 与严格结构（schema 名 `ootd_sample`，输出上限 16384 tokens）。
- 结果统一经 `OotdSchema.normalize`：形状严格（不是对象、物品超过 20 件即拒绝），词表宽松（未知取值回落为 UNKNOWN/OTHER/NA，颜色名规范化）；每件物品附 `engineRole`（推荐引擎按品类名读到的位置），审核页据此标“分类不一致”，统计页据此列出“词表候选”。
- 重复图片按原文件 SHA-256 在调用模型前拒绝（409）。
- 前端：`/admin/ootd-samples`，设置页“整套穿搭样本”（管理员可见）；推荐卡片显示“可以搭配：……”，详情显示配件理由与裤袜提示。

## 十二、风险

| 风险 | 处理 |
|---|---|
| 词表覆盖不全 | 角色 `OTHER` + 描述，统计汇总后升级 |
| 模型误判/幻觉 | 每项带置信度和可见度；人工审核后才用于统计与模板；审核时可整段修改 |
| 版权 | 上传必须选许可；"未知许可"样本只用于统计，不能生成模板草稿 |
| 未成年人 | 自动拒收 + 采集规范明确排除 |
| 偏差 | 统计按呈现分组；采集规范要求来源与人群均衡 |
| 配件建议刷屏 | 每套最多 3 条，头饰/手持物需风格相关 |

## 十三、决策记录

| 编号 | 决策 |
