# 相似衣物提示与以图搜图设计（2026-10-09）

**状态：第一期（相似衣物提示）、第二期（基础以图搜图）在分支 `feat/similar-garments` 实施；第三期（本地图像向量）待确认模型后再做。** 决策 S1~S8。总设计后续池里的“图像向量”一项由本设计接管。

## 一、要解决的问题

| 场景 | 现在 | 想要 |
|---|---|---|
| 录入时重复 | 同一件衣服拍两次、批量导入重复，衣柜里出现两件一样的，推荐里也会把它们当两件 | 入柜前后提示“衣柜里有一件几乎一样的” |
| 看一件衣服时 | 不知道自己有多少件差不多的 | 衣物详情里列出“相似的衣物”，并说明哪里像 |
| 整理衣柜 | 只能一件件翻 | 一个列表列出“可能重复”的成对衣物 |
| 以图搜图 | 只能用文字搜 | 拿一张图（截图、商品图、别人穿的）找“我有没有类似的” |

## 二、原则

1. **能不用新模型就不用**（S1）：部署时最麻烦的就是模型文件。第一、二期只用已有的东西：识图得到的字段、本地文本向量、精确取色（CIELAB）、抠图后的透明边缘，再加纯 Java 计算的图像指纹。零模型费用、零新增文件。
2. **白盒**：相似度由几项可解释的分数加权，每条结果都带“哪里像”的理由，和推荐引擎同一风格。
3. **只提示不拦截**（S2）：发现重复只提示，不自动合并、不阻止入柜；用户可以点“不是重复”让这一对以后不再提示。
4. **只在自己的衣柜里比**：不跨用户，不上传任何图片到外部。
5. **门槛先保守、再用数据校准**：初始门槛按经验设定，宁可少提示也不误报；上线后用用户的“不是重复”反馈和人工标注集调整。

## 三、相似度怎么算（第一期，S3）

### 3.1 先过门：同一个穿着位置

两件衣服必须是同一个位置（上装对上装、鞋对鞋，按推荐引擎同一套分类规则），否则不比。品类大类不同（衬衫对卫衣）直接降为“不太像”。

### 3.2 五项分数（各 0~1，缺数据的项不参与加权）

| 项 | 来源 | 计算 | 权重 |
|---|---|---|---|
| 描述 `text` | 本地文本向量（已有） | 余弦相似度，0.60 以下记 0，0.95 以上记 1，中间线性 | 0.30 |
| 颜色 `color` | 精确取色（已有） | 主色与第二色按占比加权的 ΔE，ΔE≤4 记 1，≥30 记 0 | 0.25 |
| 轮廓 `shape` | **新增图像指纹**：抠图后透明区域的 8×8 占位网格 + 长宽比 | 网格交并比 × 长宽比接近度 | 0.20 |
| 外观 `look` | **新增图像指纹**：64 位感知哈希（pHash，DCT） | 1 − 汉明距离/32，下限 0 | 0.15 |

颜色项按两边色板互相比对（每块颜色到对方最近颜色的 ΔE，按占比加权，取两个方向中较大者），这样“一件有白色条纹、一件没有”不会被平均掉。
| 字段 `fields` | 识图字段（已有） | 品类、图案、袖长、领型、长度逐项相同的比例 | 0.10 |

总分 = 有数据的项按权重加权平均。另附一个**近乎相同**判定：pHash 汉明距离 ≤ 4 且颜色 ≥ 0.85（同一张图或连拍）。识图字段里**品类或图案明确不同**时，无论图片多像都不算重复（理由里写“但图案不同”）。

### 3.3 等级

| 等级 | 条件（初始值） | 用法 |
|---|---|---|
| `DUPLICATE` 可能重复 | 近乎相同；或总分 ≥ 0.90 且颜色 ≥ 0.85 且轮廓 ≥ 0.75 | 入柜前后与详情页醒目提示 |
| `VERY_SIMILAR` 非常像 | 总分 ≥ 0.80 | 详情页列出 |
| `SIMILAR` 相似 | 总分 ≥ 0.68 | 详情页列出（排在后面） |

### 3.4 理由示例

“颜色几乎一样（ΔE 3）”、“轮廓很接近”、“描述相似度 0.93”、“同一张图或几乎相同的图”、“品类与图案相同”。

### 3.5 图像指纹（新增，纯 Java）

- 读展示图（已抠图的透明 PNG 优先），按透明度裁到衣物外框；没有透明度时按与背景色的差异估计外框。
- 感知哈希：衣物合成到白底 → 32×32 灰度 → DCT → 取左上 8×8（去掉直流）与中位数比较 → 64 位。
- 轮廓：外框内按透明度做 8×8 占位网格（64 位）+ 外框长宽比。
- 与取色一样**绑定展示图**：换展示图就重算；后台任务 `VISUAL_INDEX` 每 30 秒扫描补算，零模型调用。

## 四、第一期功能

| 位置 | 功能 |
|---|---|
| 衣物详情 | “相似的衣物”：最多 5 件，缩略图 + 等级 + 理由；有 `DUPLICATE` 时顶部提示“衣柜里有一件几乎一样的”，可点“不是重复” |
| 未入柜（待入柜）页 | 每件草稿若与已入柜衣物 `DUPLICATE`，卡片上标“可能重复” |
| 设置 → 整理衣柜 | “可能重复的衣物”成对列出，可逐对标“不是重复”或去删除其中一件 |
| 接口 | `GET /api/garments/{id}/similar`、`GET /api/garments/duplicates`、`POST /api/garments/similar-dismissals`（标“不是重复”）、`GET /api/garments/similar-flags?ids=`（批量查草稿是否疑似重复） |

“不是重复”存在 `garment_similar_dismissal`（按无序对存储），之后这对不再出现在重复提示里，但仍可出现在“相似的衣物”中（降为 `VERY_SIMILAR`）。

## 五、第二期：基础以图搜图（不加模型，S4）

用户上传一张图（可选告诉系统找的是哪个位置，如“上装”）：

1. 本地抠图（有 U²-Net 用它，没有用 GRABCUT；输入先缩到长边 640）→ 剔除与背景色（图像边缘中位色）很接近的残留像素（剔除超过 60% 时视为衣服与背景同色，保留原抠图）→ 取色 → 图像指纹。
2. 与衣柜里同位置（未指定则全部）衣物比颜色、轮廓、外观三项（没有文字描述可比）。
3. 返回最像的 10 件和理由。

**能力边界写清楚**：不加图像模型时，能找到的是“颜色和轮廓都像的”和“同一张或几乎相同的图”（例如截图了自己的商品页）；**认不出“同款不同拍法”**（换了角度、光线、穿在身上 vs 平铺）。界面上明确说明，并引导第三期。

可选：勾选“先识图”（消耗一次识图额度）后，用识图得到的品类和颜色名过门、再用文本向量比描述，效果明显更好。默认不勾，零费用。

## 六、第三期：本地图像向量（待确认，S5~S7）

真正的“以图搜图”（换角度、换光线、平铺对上身也能认出）需要一个本地图像向量模型，ONNX 运行、和文本向量一样“后装免重启”、不自动下载：

| 候选 | 特点 | 需要核实 |
|---|---|---|
| Chinese-CLIP（ViT-B/16） | 中文图文同一空间，还能“用文字搜图片”（如“找那件有小熊图案的”） | 模型大小、许可证、ONNX 导出与精度 |
| FashionCLIP（ViT-B/32） | 在服饰数据上微调，服饰相似度更准；英文文本 | 许可证、大小 |
| MobileCLIP 一类小模型 | 体积小、CPU 快 | 服饰效果、许可证 |

做法：为每件衣物的展示图（抠图后）算一个图像向量，绑定展示图版本存储；以图搜图与相似衣物都多一项 `image` 分数（权重最高）；用户上传的查询图同样抠图后编码。需要你决定：**用哪个模型、能接受多大的模型文件**。我建议先用 50~100 件真实衣物 + 人工标注的“同款/相似/不同”对做评估，再定模型和门槛。

## 八、测试

- 图像指纹：同图同哈希；轻微缩放/压缩后汉明距离小；不同形状衣物轮廓分数低；透明与不透明图都能取外框。
- 相似度：同色同款高于同款异色高于异款；不同位置不比；缺文本向量时其余项照常加权；理由与分数一致。
- 等级与“不是重复”：标记后不再出现在重复列表；对称（A-B 与 B-A 同一条）。
- 接口：只能查自己的衣物（他人 404）；草稿批量查询；以图搜图对同一张图返回 `DUPLICATE`。
- 后台补算：换展示图后重算。

## 九、实测修正（2026-10-09 自测）

| 现象 | 原因 | 修正 |
|---|---|---|
| 条纹 T 恤与纯色 T 恤被判“可能重复” | 感知哈希只差 6 位卡在门槛上；颜色只比主色、第二色被平均 | 近乎相同门槛收紧为 4 位；颜色改为两边色板互比取较大者；品类或图案字段不同时一票否决 |
| 浅色背景照片搜纯色 T 恤，条纹 T 恤排第一 | GRABCUT 把约 12.6% 的背景留在了衣服里，色板多出一块近白色 | 抠图后剔除与背景色相近的像素；修正后两件纯色 T 恤 0.83 在前、条纹 0.69 在后 |
| 以图搜图首次约 3 秒 | 本地抠图库首次加载 | 输入缩到 640；之后每次约 0.7 秒 |
