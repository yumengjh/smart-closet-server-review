# 大屏演示数据与布局设计

日期：2026-10-21 · 相关：[管理接口二期](2026-10-09-管理接口二期：运维、KPI与大屏数据设计.md)第七节、[MANAGEMENT_API.md](../MANAGEMENT_API.md)

## 1. 背景

后台首页（业务大屏）只有 2 个真实用户、270 件衣物，曲线大多贴着 0、指标常为 0，看不出“大数据展示”的效果；板块也只有 9 个且大小一样。需要两件事：足量、形态真实的演示数据，以及更丰富的大屏板块。

## 2. 快照新增数据（管理接口 1.2）

`GET /api/manage/v1/dashboard/snapshot` 增加，全部是汇总，不含用户名、衣物名称、图片：

| 字段 | 内容 |
| --- | --- |
| `growth` | 近 30 天每日新增用户、当日结束时的累计用户 |
| `heatmap` | 近 28 天有记录的操作按星期（1=周一）× 小时（北京时间）计数，口径同“活跃用户”的操作来源 |
| `feed` | 全站最新 20 条动态：类型、时间，以及衣物大类键或注册来源；不含任何身份或物品名称 |
| `distributions.styles` / `genderFits` | 衣物风格标签前 12、男款/女款/中性 |
| `distributions.closetSizes` | 用户按已入柜衣物数分档（0、1–9、10–29、30–59、60+），含空衣柜 |
| `distributions.registeredVia` | 账号来源 |
| `distributions.aiFeatures30d` | 近 30 天按功能的模型调用次数与 Token |

`/insights/wardrobe` 同步增加 `styles`、`genderFits`。

## 3. 大屏布局

四行，1080 高度一屏放下，窗口更矮时页面滚动而不是压缩图表：

1. 指标：业务用户、有效衣物、保存搭配、今日推荐、今日活跃（7 日 / 30 日 / 在线）、运行状态（右上角为大屏设置）。
2. 衣柜品类构成 · 业务活动趋势 · 推荐采用。
3. 风格偏好 TOP · 活跃时段热力 · 实时动态（循环滚动、悬停暂停、尊重减少动态）。
4. 衣物颜色 TOP · 用户增长（注册来源、衣柜规模分档）· 季节与版型 · AI 用量（按功能 Token）。

## 4. 演示数据

`scripts/demo-data/generate_demo_sql.py` 生成 SQL，服务停止时用 H2 `RunScript` 写入；`cleanup_demo.sql` 删除全部演示数据。

- 账号一律以 `demo_` 开头，密码哈希为随机值，不能登录。
- 注册时间在最近 N 天内逐步加速；活跃按用户分层（帕累托分布），工作日/周末与早午晚高峰加权。
- 衣物复制现有真实衣物：同一图片资产、识别结果与已算好的派生索引（颜色、视觉指纹、图像向量、画风、查重、文本向量）。因此不会触发任何后台重算，也不调用模型；识别结果没有 `genderFit` 的，在用户覆盖里写入版型，避免进入性别适配补算（该补算会调用识别模型）。
- 推荐记录按真实来源比例（推荐页、换一批、助手、今日灵感、换一件），并生成点赞、打开组合台、3 天内穿着等采用信号，使采用率落在真实区间。
- 同时生成搭配、穿着记录、助手与识别用量、每日额度、账号事件。

使用：

```bash
# 停止服务、备份 data/db 后
N=<真实已入柜衣物数>
python3 scripts/demo-data/generate_demo_sql.py --users 360 --days 60 --sources $N > /tmp/demo.sql
java -cp ~/.m2/repository/com/h2database/h2/2.4.240/h2-2.4.240.jar org.h2.tools.RunScript \
  -url jdbc:h2:file:$PWD/data/db/closet -user sa -script /tmp/demo.sql
# 撤销
java -cp …/h2-2.4.240.jar org.h2.tools.RunScript -url jdbc:h2:file:$PWD/data/db/closet -user sa -script scripts/demo-data/cleanup_demo.sql
```

演示数据是一次性写入的，“今日”类指标只在写入当天有值；需要时先清理再按当前时间重新生成。
