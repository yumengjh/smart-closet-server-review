# 管理接口二期：运维、KPI 与大屏数据设计（2026-10-09）

**状态：已实施（分支 `feat/management-ops-kpi`，基于 `feat/outfit-fullbody`）。** 一期设计见 [管理平台接入与可插拔管理接口设计](2026-10-07-管理平台接入与可插拔管理接口设计.md)，接入方式（HMAC 签名、错误格式、开关）完全沿用，见 [管理接口接入指南](../MANAGEMENT_API.md)。契约文件 [management-api.yaml](../management-api.yaml)。决策记录 M1~M10。

## 一、背景

一期只有两块：用户管理（列表、启停、角色、重置密码、会话、额度）与衣柜洞察（概览、衣柜构成、使用率、日/周趋势）。之后要接管理平台的运维页面和大数据展示大屏，缺：

| 缺口 | 影响 |
|---|---|
| 运维状态 | 不知道模型装没装、语义索引补了多少、任务队列有没有积压、磁盘还剩多少、Agent 运行时通不通 |
| 失败任务、管理操作日志 | 出了问题只能上服务器看日志 |
| 推荐与模型 KPI | 推荐采用率、各来源效果、模型 token 用量只有用户自己在设置页能看到，平台层面没有 |
| 大屏数据 | 大屏需要“一次请求拿全部指标块”、近 24 小时逐小时曲线、在线人数，且不能带用户名 |
| 数仓接入 | 大数据平台需要按天的宽表与可增量拉取的明细事件，且明细必须去标识 |
| 模板审核 | 只能在鱼搭里用管理员账号审，管理平台无法接 |

## 二、原则（M1）

1. **沿用一期的边界**：服务对服务、HMAC 签名、默认关闭、核心代码不依赖管理模块、不读用户图片与私密媒体。
2. **只读为主**：新增接口中只有模板审核是写操作，并记入操作日志。不提供重试/取消任务、改配置等“远程运维”能力（风险大，留到确有需要时单独设计）。
3. **大屏与数仓接口不带用户名**（M2）：大屏只给汇总；明细事件用不可逆的用户别名 `userKey`（HMAC-SHA256，盐可配置）。需要对应真实账号时，由管理员在用户接口里查，不在数据出口里带。
4. **口径写进文档、写进响应**：每个指标在本文第八节有定义；采用率等容易误解的指标在响应里附 `definition`。
5. **成本**：全部用 SQL 聚合与短缓存计算，不调用模型；大屏快照缓存 15 秒，其他沿用 `insights-cache-ttl`（默认 60 秒）。

## 三、接口一览

基础路径 `/api/manage/v1`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/ops/status` | 运维总览：总体状态与原因、应用与 JVM、存储与数据库文件、模型与索引覆盖、任务队列、服务商与 Agent 运行时、在线会话 |
| GET | `/ops/tasks` | 后台任务列表（按状态、类型筛选，分页），含错误摘要 |
| GET | `/ops/operation-log` | 管理接口操作日志（按时间、动作、目标用户筛选，分页） |
| GET | `/insights/recommendations` | 推荐效果 KPI：展示、采用、采用率、点赞/点踩、打开搭台、3 天内穿、换一件、按来源/名次、模板命中 |
| GET | `/insights/ai` | 模型与额度用量：按功能的调用次数与 token、生图额度、助手消息、零模型推荐占比 |
| GET | `/insights/trends` | 一期接口，**新增指标**（见第六节） |
| GET | `/dashboard/snapshot` | 大屏一次拿全：指标块、近 24 小时逐小时曲线、分布、推荐来源、运维摘要 |
| GET | `/exports/daily` | 按天宽表（JSON 或 CSV），最长 366 天 |
| GET | `/exports/events` | 去标识明细事件，游标增量拉取 |
| GET | `/templates` | 搭配模板列表（含审核状态、来源） |
| PATCH | `/templates/{id}` | 审核模板：状态、启用、加分 |

## 四、运维（M3）

### 4.1 `/ops/status`

```jsonc
{
  "status": "UP",                    // UP / DEGRADED（有需要关注的问题，但服务可用）
  "issues": [{"code": "EMBEDDING_MODEL_MISSING", "message": "…"}],
  "app": {"version": "0.0.1-SNAPSHOT", "startedAtMs": 0, "uptimeMs": 0, "java": "21.0.x"},
  "jvm": {"heapUsedBytes": 0, "heapMaxBytes": 0, "nonHeapUsedBytes": 0, "threads": 0, "processors": 4, "systemLoadAverage": 0.5, "processCpuLoad": 0.1},
  "storage": {"path": "/data", "totalBytes": 0, "usableBytes": 0, "usedRatio": 0.4, "databaseBytes": 0},
  "models": {"segmentation": {"present": true, "loaded": false}, "embedding": {"available": true, "version": "local-text-cls-v1:…"}},
  "indexes": {"semantic": {"indexed": 0, "total": 0, "coverage": 1.0}, "color": {"measured": 0, "total": 0, "coverage": 1.0}},
  "queue": {"byStatus": {"QUEUED": 0, "RUNNING": 0, "WAITING_QUOTA": 0}, "byKind": [{"kind": "SEMANTIC_INDEX", "queued": 0, "running": 0, "waitingQuota": 0, "failed24h": 0}],
            "oldestQueuedAgeMs": null, "failed24h": 0},
  "providers": {"recognition": {"defaultProvider": "yumg", "configured": true}, "generation": [{"id": "yumg", "configured": true}],
                "agentRuntime": {"reachable": true, "latencyMs": 12}},
  "sessions": {"active": 0, "onlineLast5Min": 0},
  "generatedAtMs": 0
}
```

- 不返回任何密钥、服务商地址或用户名。
- `issues` 的判定（全部可在配置里关闭阈值）：向量模型缺失 `EMBEDDING_MODEL_MISSING`；抠图模型缺失 `SEGMENTATION_MODEL_MISSING`；语义索引覆盖率 < 90% 且模型可用 `SEMANTIC_INDEX_BEHIND`；排队最久的任务超过 10 分钟 `QUEUE_BACKLOG`；24 小时失败任务 ≥ 10 `TASK_FAILURES`；存储使用率 ≥ 90% `DISK_FULL`；识图服务商未配置 `RECOGNITION_NOT_CONFIGURED`；Agent 运行时连不上 `AGENT_RUNTIME_UNREACHABLE`。
- Agent 运行时探测：`GET {runtimeUrl}/health`，超时 1 秒，结果缓存 15 秒。
- `databaseBytes`：H2 文件库时为 `.mv.db` 文件大小，其他数据库为 null。

### 4.2 `/ops/tasks`

参数 `status`（QUEUED/RUNNING/WAITING_QUOTA/FAILED/SUCCEEDED/CANCELLED，可多值，默认 FAILED）、`kind`、`page`、`size`。返回 `{items:[{id, kind, ownerUsername, status, stage, pool, priority, waitReason, errorMessage(截断 300), attempts, createdAtMs, updatedAtMs, nextRunAtMs}], total, page, size}`。不返回任务载荷（可能含图片引用）。

### 4.3 `/ops/operation-log`

参数 `from`、`to`（日期）、`action`、`targetUsername`、`page`、`size`。返回一期写入的 `management_operation_log` 行（时间、密钥 ID、操作人、请求 ID、动作、目标、结果、摘要）。

## 五、KPI（M4、M5）

### 5.1 `/insights/recommendations`

参数 `username`（可选）、`from`、`to`。口径与用户设置页“推荐效果”一致（P4 D39），平台级按用户分别匹配后汇总：

| 字段 | 定义 |
|---|---|
| `shown` | 范围内展示给用户的推荐套数（`recommendation_log` 行数） |
| `adopted` / `adoptionRate` | 采用＝点赞、在搭台打开、或展示后 3 天内打卡穿过这一套里的全部衣物 |
| `liked` / `disliked` / `likeRate` | 点赞、点踩的套数；点赞率＝点赞/（点赞+点踩） |
| `openedInWorkspace`、`wornWithin3Days`、`swaps` | 分项 |
| `users` | 范围内收到过推荐的用户数 |
| `bySource` | 按来源（PAGE 推荐区、AGENT 助手、INSPIRATION 今日灵感等）的展示与采用 |
| `byRank` | 第 1/2/3 名的展示与采用（看排序是否有效） |
| `templates` | 命中模板的展示数 Top 10 与采用率 |
| `daily` | 每天的展示与采用 |

### 5.2 `/insights/ai`

| 字段 | 定义 |
|---|---|
| `byFeature` | `model_usage` 按功能（AGENT 助手、OOTD_EXTRACT 整套样本提取…）：调用次数、输入/输出 token、用量未知次数 |
| `imageUnits` | 生图/识图额度消耗（`ai_daily_quota`） |
| `agentMessages` | 助手消息数（`agent_daily_quota`） |
| `recommendations` | 推荐总数、其中零模型（非助手来源）的数量与占比 |
| `topUsers` | 只在不传 `username` 时返回：按 token 用量 Top 10 的用户名（管理平台用于排查异常用量，属于运维视图，不进大屏） |

费用不在鱼搭换算（单价随服务商变化）；接入方用 token 数乘自己的单价。

## 六、趋势新增指标（M6）

一期 `GET /insights/trends` 的 `metric` 新增：

| 指标 | 定义 |
|---|---|
| `active_users` | 当天有操作的用户数：新增衣物、新建搭配、收到推荐、反馈、行为信号、打卡、助手消息、生图/识图额度消耗，任一即算（近似 DAU，不含只浏览不操作的） |
| `recommendations_shown` | 当天展示的推荐套数 |
| `recommendation_likes` / `recommendation_dislikes` | 当天的点赞/点踩 |
| `wear_logs` | 当天的打卡次数 |
| `model_calls` / `model_tokens` | 当天的模型调用次数 / 输入+输出 token |
| `ootd_samples` | 当天上传的整套穿搭样本 |

`granularity` 新增 `month`。

## 七、大屏与数仓（M7、M8、M9）

### 7.1 `/dashboard/snapshot`（大屏）

一次请求返回大屏需要的全部数据，缓存 15 秒，建议大屏每 30~60 秒轮询一次（响应里有 `refreshAfterMs`）。**不含任何用户名或衣物名称。**

```jsonc
{
  "generatedAtMs": 0, "refreshAfterMs": 30000,
  "tiles": {
    "usersTotal": 0, "usersNewToday": 0, "activeToday": 0, "active7d": 0, "active30d": 0, "onlineNow": 0,
    "garmentsActive": 0, "garmentsToday": 0, "outfitsTotal": 0, "outfitsToday": 0,
    "recommendationsToday": 0, "adoptionRate7d": 0.31, "wearLogsToday": 0,
    "agentMessagesToday": 0, "imageUnitsToday": 0, "modelTokensToday": 0
  },
  "hourly": {"hours": ["2026-10-09T10:00+08:00", …24 项], "series": [{"metric": "garments_created", "values": […]}, …]},
  "daily": {"days": [… 近 30 天], "series": [{"metric": "active_users", "values": […]}, …]},
  "distributions": {"categories": [{"key": "上装", "count": 0}], "colors": […Top 10], "seasons": […], "recommendationSources7d": [{"key": "PAGE", "shown": 0, "adopted": 0}]},
  "ops": {"status": "UP", "issues": 0, "queueBacklog": 0, "failed24h": 0}
}
```

逐小时序列：`garments_created`、`outfits_created`、`recommendations_shown`、`model_calls`、`active_users`（该小时有操作的用户数）。

### 7.2 `/exports/daily`（按天宽表）

参数 `from`、`to`（最长 366 天）、`format=json|csv`。每天一行，列：`date, users_created, active_users, garments_created, garments_adopted, outfits_created, quick_intakes, recommendations_shown, recommendation_likes, recommendation_dislikes, wear_logs, agent_messages, image_units, model_calls, input_tokens, output_tokens, ootd_samples`。CSV 带表头、UTF-8、逗号分隔，适合直接导入 BI 或数仓。

### 7.3 `/exports/events`（去标识明细，增量）

参数 `cursor`（上次返回的 `nextCursor`，首次不传则从最早开始；也可传 `since`=毫秒时间戳）、`limit`（1~1000，默认 500）、`types`（可多值，默认全部）。

```jsonc
{"items": [{"type": "recommendation_shown", "id": "…", "atMs": 0, "userKey": "3f9a…(16 位)", "attrs": {"source": "PAGE", "rank": 1, "score": 86.5, "template": "white-tee-denim-sneaker"}}],
 "nextCursor": "…", "hasMore": true, "watermarkMs": 0}
```

| 事件 | attrs |
|---|---|
| `user_created` | `role` |
| `garment_created` | `status`（ACTIVE/DRAFT…）、`family`（品类大类） |
| `outfit_created` | `items`（件数） |
| `recommendation_shown` | `source`、`rank`、`score`、`template` |
| `recommendation_feedback` | `verdict`（UP/DOWN）、`reasons` |
| `wear_logged` | `items` |
| `model_usage` | `feature`、`model`、`inputTokens`、`outputTokens` |
| `quick_intake` | `status` |

- 排序键 `(atMs, type, id)`，游标是它的不透明编码；同一游标重复拉取结果一致（幂等），接入方失败可安全重试。
- `watermarkMs = 当前时间 − 5 秒`：只返回此前的事件，避免并发写入导致漏拉。
- `userKey = HMAC-SHA256(盐, 用户名)` 的前 16 位十六进制。盐取 `closet.management.export-salt`（环境变量 `CLOSET_MANAGEMENT_EXPORT_SALT`）；未配置时由第一把管理密钥派生。**更换盐会让所有 userKey 改变**，数仓需要按新旧盐分段。
- 明细不含用户名、衣物名称、图片、聊天内容、意图原文。

## 八、模板审核（M10）

`GET /templates`：与鱼搭模板审核页相同的数据（资源文件模板 + 样本生成的草稿），附 `source`（FILE/SAMPLE）。
`PATCH /templates/{id}`：`{reviewStatus?, enabled?, bonus?}`，与鱼搭管理员审核同一份存储，立即生效；审核人记为 `manage:{keyId}:{X-Operator}`，并写操作日志。

## 九、配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `closet.management.dashboard-cache-ttl` | 15s | 大屏快照缓存 |
| `closet.management.export-salt` | 空（由密钥派生） | 明细事件用户别名的盐 |
| `closet.management.ops.queue-backlog-warn` | 10m | 排队最久超过多久算积压 |
| `closet.management.ops.failed-tasks-warn` | 10 | 24 小时失败任务数阈值 |
| `closet.management.ops.disk-used-warn` | 0.9 | 存储使用率阈值 |
| `closet.management.ops.semantic-coverage-warn` | 0.9 | 语义索引覆盖率阈值 |

## 十、测试

- 契约测试：`management-api.yaml` 与实现路由一致（一期已有，自动覆盖新路由）。
- 架构测试：核心不依赖管理模块、管理 bean 全部受开关控制（一期已有）。
- 新增接口测试：签名校验、运维状态字段与 issues 判定、任务筛选、操作日志、推荐 KPI 口径（点赞/打开/3 天内穿 各一例 + 不同用户不串）、AI 用量按功能、趋势新指标、大屏快照不含用户名、按天宽表 JSON 与 CSV 一致、明细事件游标翻页不重不漏且 userKey 稳定、模板审核写日志。

## 十一、不做（后续）

- 远程重试/取消任务、改配置、清缓存等写操作。
- Prometheus 指标端点（需要独立于 HMAC 的抓取认证；运维状态接口已覆盖主要指标，管理后端可代为暴露）。
- 实时推送（WebSocket/SSE）：大屏轮询快照即可，15 秒缓存保证压力可控。
- 按服务商单价换算费用。

## 十二、决策记录

| 编号 | 决策 |
|---|---|
| M1 | 沿用一期边界（HMAC、默认关闭、单向依赖、不读图片与私密媒体）；新增以只读为主 |
| M2 | 大屏只给汇总，明细事件只给不可逆用户别名；需要真实账号时走用户接口 |
| M3 | 运维状态给出总体状态与可读原因，阈值可配置；不暴露密钥、地址、用户名 |
| M4 | 推荐 KPI 与用户设置页口径一致，平台级按用户分别匹配后汇总 |
| M5 | 费用只给 token 数，单价由接入方换算 |
| M6 | 活跃用户定义为“有操作”，基于已记录的写操作与用量，近似 DAU，文档写明 |
| M7 | 大屏一次请求拿全，15 秒缓存，响应带建议刷新间隔 |
| M8 | 数仓用按天宽表（JSON/CSV）+ 游标增量明细，排序键 (atMs,type,id)，5 秒水位线 |
| M9 | 用户别名的盐可配置，未配置时从管理密钥派生；换盐即换别名 |
| M10 | 模板审核开放给管理接口，与鱼搭管理员审核共用存储，写操作日志 |
