# 当前多件合图设计与现有功能

以 `../smart-closet/src/components/SpriteTrial.vue`、批次页面以及用户提供的 localhost:8080 批次为依据。网站仍保持原来的运行行为，本稿是待审计的界面方案。

| 功能 | 现有行为 | 当前设计 |
| --- | --- | --- |
| 多图模式、选图、实验功能 | 多件入口可上传照片，再开启合图试用 | 01 选照片保留选图、拍照与合图入口，识别后进入 02 选衣物 |
| 合图与逐件 | groupSize=1 时主按钮变为“逐件试用”；本地会恢复该值 | 两个模式入口明确区分；合图界面建议从每组 2 件起，1 件模式通过逐件入口保留 |
| 每组件数 | 1–min(10,可处理件数) | 常用 2/3/4/6 直接选；齿轮展开自定义，保留至 10，上限仍受本批次可处理件数约束 |
| 选择目标 | 指定 targetIds，保留来源顺序 | 同样按衣物身份选择，六张局部缩略图；没有重复整张原图 |
| 只选一组、全选 | firstGroup / selectAll | 两个按钮保留；原型只在默认 2 件分组连接固定演示状态 |
| 分组与额度 | ceil(选中件数 / 每组件数) | 件数、组数和次数同时显示，CTA 同步；4/4=1、4/2=2、4/3=2、6/2=3 |
| 原图对照 | 来源照片可查 | 一份统一原图弹层，图片图标入口；多来源按 sourceId 查对应来源，避免每张衣物卡重复来源照片 |
| 合图后的处理 | 生成、拆分、透明处理、贴纸依次自动执行；本地阶段不增加 AI 额度 | 03 自动处理进度明确四个阶段；不要求每件点击一次“制作贴纸” |
| 贴纸暂停恢复 | 暂停或失败可恢复单件本地处理 | 原有恢复稿保留在异常区域，改名标明“例外”，移出多件主线 |
| 结果与入柜 | 处理完成与确认入柜是不同状态；批次详情保留对应衣物操作 | 04 结果列表明确“处理完成 · 尚未入柜”；不冒充已保存入柜。详情核对、编辑、入柜和重做沿用已有功能，本轮未重新设计这些详情 |
| 单件录入 | 原有“识别并整理”可一次开始处理 | 本轮没有给单件追加强制核对步骤，也未替换原有单件页面 |
| 原站布局 | 原侧栏、主题/声音 SVG、助手、手机导航 | 使用原图层；60 处全局图层内容与原型源层签名一致 |

## 验证与边界

当前 25 张原生图层已逐张导出，检查 156 个按钮文字居中、内容边界和 146 个原型控件引用，未发现越界或失效目的地。核心桌面/手机选择、进度、照片、结果与自定义弹层已目视复核。局部图裁切沿用实际批次 bounds；白边或相邻衣物片段不作为生成质量证据。

原型是固定状态演示，尚不支持任意勾选、真实上传、自由分组、计费或入柜。本地 `.fig` 保存与原生截图不能证明 Figma 云同步成功。应用代码和错误处理未实施。
