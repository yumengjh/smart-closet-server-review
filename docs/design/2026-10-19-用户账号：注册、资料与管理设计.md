# 用户账号：注册、资料与管理设计

日期：2026-10-19 · 使用说明：帮助文章 `src/main/resources/help/05-account.md` · 管理接口：[MANAGEMENT_API.md](../MANAGEMENT_API.md) 第 5、15 节

## 1. 背景

鱼搭要正式上线。现在的账号体系只够内测：

| 现状 | 上线的缺口 |
| --- | --- |
| 账号只能由管理员（CLI、`/api/manage/v1`）创建，登录页写“使用受邀账号登录” | 用户不能自己注册；管理员要一个个发临时密码 |
| 用户只有用户名、角色、启用状态 | 没有昵称，界面只能显示用户名；看不到最近登录时间 |
| 只能改密码、生成便携链接 | 看不到自己在哪些设备登录，不能一键退出其他设备；改密码不会退出其他设备；不能自己注销 |
| 登录不限次数 | 公网上线后可被暴力猜密码；停用账号的报错路径与密码错误不同，可借此探测账号 |
| 管理只有默认关闭的 `/api/manage/v1` | 没接管理平台的部署里，管理员在鱼搭里没有任何用户管理界面 |

## 2. 目标与不做的事

目标：

1. **注册**：三种模式 `CLOSED` / `INVITE` / `OPEN`，默认 `INVITE`。邀请码由管理员生成，可限次数、限有效期、可撤销。自助注册的账号直接可用，不需要再改密码。
2. **个人资料**：昵称（展示名），用户名不可改；显示注册时间、最近登录时间、注册来源。
3. **账号安全**：登录设备列表，退出其他设备；改密码默认同时退出其他设备；自助注销（停用并登记）。
4. **防滥用**：登录失败限流、注册按来源地址限流，错误信息不暴露账号是否存在或已停用。
5. **鱼搭内的用户管理**：管理员在“我的 → 用户管理”里查找用户、创建、启用/停用、改角色、重置密码、退出会话、调整额度，并管理邀请码。
6. **管理接口同步暴露**：`/api/manage/v1` 增加邀请码、注册配置（只读）与账号事件（只读），用户列表与详情增加新字段。管理平台（`../smart-closet-admin`）本次不改，接口向后兼容，新增字段对旧客户端无害。

不做：

- 不做邮箱 / 手机号与找回密码：没有可靠的邮件、短信通道，存了也无法验证。忘记密码由管理员重置（已有能力）。列入后续。
- 不支持改用户名：用户名是全部业务表的 `owner_username` 外键。
- 不做物理删除数据：注销 = 停用 + 登记注销时间，数据保留，管理员可恢复。彻底清除涉及图片存储与几十张表，单独设计（后续）。
- 不做头像上传：沿用首字母头像。
- 不做验证码：先用限流挡住暴力请求，验证码视上线后情况再加。

## 3. 数据

迁移 `V28__user_accounts.sql`：

```sql
ALTER TABLE closet_user ADD COLUMN display_name VARCHAR(40);
ALTER TABLE closet_user ADD COLUMN last_login_at_ms BIGINT;
ALTER TABLE closet_user ADD COLUMN registered_via VARCHAR(16) DEFAULT 'ADMIN' NOT NULL;  -- ADMIN / INVITE / OPEN
ALTER TABLE closet_user ADD COLUMN invite_id VARCHAR(36);
ALTER TABLE closet_user ADD COLUMN deactivated_at_ms BIGINT;  -- 用户自助注销时间；管理员重新启用时清空

CREATE TABLE registration_invite (id, code_hash UNIQUE, note, max_uses, used_count, created_by, created_at_ms, expires_at_ms, revoked_at_ms);
CREATE TABLE account_event (id, occurred_at_ms, username, actor, action, detail);
```

- 邀请码明文只在创建响应里出现一次，库里只存 SHA-256。格式 `XXXX-XXXX-XXXX`（去掉易混字符的大写字母与数字，约 60 位熵）。
- `account_event` 记录账号层面的事件：`REGISTERED`、`LOGIN_SUCCEEDED`（不记录失败，失败只进限流计数）、`PASSWORD_CHANGED`、`PROFILE_UPDATED`、`SESSIONS_REVOKED`、`DEACTIVATED`，以及鱼搭内管理员操作 `ADMIN_*`。`actor` 是操作者用户名，管理员代操作时与 `username` 不同。不记录密码、邀请码明文、IP、UA。保留最近 180 天，每次写入时按概率清理。
- 昵称：去首尾空白后 1–40 个字符，不允许控制字符；为空表示未设置，界面回退显示用户名。

## 4. 注册

配置 `closet.account.registration`（环境变量 `CLOSET_REGISTRATION`），默认 `INVITE`；管理接口 `PUT /registration` 可覆盖，覆盖值优先：

| 模式 | 行为 |
| --- | --- |
| `CLOSED` | 登录页不显示注册入口，注册接口返回 403 `REGISTRATION_CLOSED` |
| `INVITE` | 必须填有效邀请码；没有发出过邀请码时等同关闭，但入口仍在（用户可能拿着链接来） |
| `OPEN` | 任何人可注册，邀请码可不填；填了也会核销并记录来源 |

流程 `POST /api/auth/register`：校验模式与输入 → 来源地址限流 → 在一个事务里条件更新邀请码 `used_count = used_count + 1 WHERE 有效 AND used_count < max_uses`（并发安全） → 创建 `USER` 账号（`must_change_password=0`，`registered_via`、`invite_id`） → 写事件 → 与登录相同的方式建立新会话并返回当前用户。用户名已存在返回 409 `USERNAME_TAKEN`（注册必然暴露用户名是否被占用，这是所有注册系统的共性，靠限流降低枚举速度）。

邀请链接：`/register?invite=XXXX-XXXX-XXXX`。这是查询参数而不是 fragment，会进入访问日志；邀请码只能用于注册新账号、不能登录已有账号，泄露的后果是多一个注册名额，可撤销，因此可接受。

## 5. 登录与限流

`LoginThrottle`（内存，单实例；便携版与容器版都是单实例）：

- 按“用户名（小写）”与“来源地址”两个键分别计数，15 分钟窗口内失败 5 次（用户名）/ 20 次（地址）即拒绝，返回 429 `LOGIN_THROTTLED` 和 `Retry-After`。成功登录清空该用户名的计数。
- 注册：同一来源地址每小时 5 次。
- 来源地址取 `request.getRemoteAddr()`；`server.forward-headers-strategy=native` 已让受信反向代理传递真实地址。
- 所有认证失败（密码错、账号不存在、已停用、已锁）统一返回 401“账号或密码不正确。”。之前停用账号会走到异常分支，现在一并收口。
- 登录成功更新 `last_login_at_ms`，写 `LOGIN_SUCCEEDED` 事件；会话上记录 `closet.device`（由 User-Agent 归纳出的“浏览器 · 系统”，例如“Chrome · macOS”，不存原始 UA）供设备列表显示。

## 6. 用户自己的接口（`/api/auth/*`，需登录、带 CSRF）

| 接口 | 说明 |
| --- | --- |
| `GET /api/auth/registration` | 匿名可访问：`{"mode":"INVITE"}` |
| `POST /api/auth/register` | 匿名可访问：`{username, password, displayName?, inviteCode?}` → 200 当前用户；错误码 `REGISTRATION_CLOSED`(403) `INVITE_REQUIRED`/`INVITE_INVALID`/`INVALID_REQUEST`(400) `USERNAME_TAKEN`(409) `REGISTRATION_THROTTLED`(429) |
| `GET /api/auth/me` | 增加 `displayName` |
| `GET /api/auth/profile` | `{username, displayName, role, createdAtMs, lastLoginAtMs, registeredVia}` |
| `PATCH /api/auth/profile` | `{displayName}`（`null` 或空串清除） → 新的 profile；首登未改密码时不可用 |
| `GET /api/auth/sessions` | `[{sessionRef, device, createdAtMs, lastAccessAtMs, expiresAtMs, portable, current}]` |
| `DELETE /api/auth/sessions/others` | 退出其他设备 → `{"revokedSessions": n}`；同时吊销该账号的便携登录授权 |
| `POST /api/auth/password` | 增加可选 `signOutOthers`（默认 `true`）：改密码后删除除当前会话外的全部会话 |
| `POST /api/auth/deactivate` | `{currentPassword}` → 204：停用账号、写 `deactivated_at_ms`、删除全部会话与便携授权、当前会话退出。最后一个启用的管理员不能注销（409 `LAST_ADMIN_PROTECTED`） |

便携登录会话不能改密码、不能管理设备、不能注销（与“不能管理登录授权”一致）；可以改昵称。

## 7. 鱼搭内的用户管理（`/api/admin/*`，仅管理员）

沿用 `SecurityConfiguration` 里 `/api/admin/` 前缀只允许 `ADMIN` 的规则，便携会话不能做账号管理操作（写操作返回 403）。

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/users?q=&status=ENABLED\|DISABLED&role=&page=&size=` | 分页：`{items:[{username, displayName, role, enabled, mustChangePassword, registeredVia, createdAtMs, lastLoginAtMs, deactivatedAtMs, garmentCount}], total, page, size}`；`q` 同时匹配用户名与昵称 |
| `POST /api/admin/users` | `{username, role, displayName?}` → `{username, temporaryPassword}`，临时密码只出现一次，首登必须改 |
| `PATCH /api/admin/users/{username}/status` | `{enabled}` → `{username, enabled, revokedSessions}`；不能停用自己 |
| `PATCH /api/admin/users/{username}/role` | `{role}` → `{username, role, revokedSessions}`；不能改自己的角色 |
| `POST /api/admin/users/{username}/password-reset` | `{}` → `{username, temporaryPassword, revokedSessions}` |
| `DELETE /api/admin/users/{username}/sessions` | → `{revokedSessions}` |
| `GET/PUT /api/admin/users/{username}/quota` | 与 `/api/closet/quota` 相同结构；PUT `{imageDailyLimit, agentDailyLimit}`（null 恢复默认） |
| `GET /api/admin/users/{username}/events` | 最近 50 条账号事件 |
| `GET /api/admin/registration` | `{mode, activeInviteCount}` |
| `GET /api/admin/invites` | 最近 100 条：`[{id, note, maxUses, usedCount, createdBy, createdAtMs, expiresAtMs, revokedAtMs, status}]`，`status`：`ACTIVE`/`USED_UP`/`EXPIRED`/`REVOKED` |
| `POST /api/admin/invites` | `{note?, maxUses(1–100, 默认1), expiresInDays(1–90, 默认7)}` → 邀请对象 + `code`（只出现一次） |
| `DELETE /api/admin/invites/{id}` | 撤销，204 |

与管理接口的关系：两组接口都只是核心服务（`ClosetAccountService`、`RegistrationService`、`QuotaPolicy`、`AccountEvents`）外的一层包装，规则只有一份；管理模块须可拔除，所以核心不能复用管理接口，鱼搭内这一层保留。鱼搭内页面只读注册模式，修改注册模式、改昵称、单个会话退出、解除登录锁定、修改邀请码、全站审计只在管理接口提供。

“不能停用/降级自己”避免管理员把自己锁在外面；“最后一个管理员”仍由 `ClosetAccountService` 兜底。管理员重新启用一个自助注销的账号时清空 `deactivated_at_ms`。

## 8. 管理接口（`/api/manage/v1`）

`management` 包继续单向依赖核心（新增依赖 `RegistrationService`、`AccountEvents`），契约以 `docs/management-api.yaml` 为准：

- `GET /users`、`GET /users/{username}` 增加 `displayName`、`registeredVia`、`lastLoginAtMs`、`deactivatedAtMs`；`q` 同时匹配昵称。
- `POST /users` 可选 `displayName`。
- 新增 `GET /users/{username}/events`、`GET /invites`、`POST /invites`、`DELETE /invites/{id}`。
- 完整控制（2026-10-19 第二轮，后台管理平台是正式管理入口，鱼搭内页面只是临时入口）：`PATCH /users/{u}/profile`、`DELETE /users/{u}/sessions/{sessionRef}`、`GET/DELETE /users/{u}/login-lock`、`GET/PUT /registration`（部署配置是默认值，管理覆盖存 `closet_setting`，`null` 恢复默认）、`GET/PATCH /invites/{id}`、`GET /invites` 分页与状态筛选、`GET /account-events` 全站审计；用户列表增加 `registeredVia`、`deactivated` 筛选和 `lastLoginAt` 排序，详情增加 `inviteId`、`loginLock`。迁移 `V29__closet_settings.sql`。
- 邀请码的创建者记为 `manage:{keyId}:{X-Operator}`；写操作同时进入 `management_operation_log`（`INVITE_CREATED`、`INVITE_REVOKED`）。
- 大屏与数仓出口不变，不出现昵称。

## 9. 前端（`../smart-closet`）

- 登录页：注册模式非 `CLOSED` 时显示“注册账号”；文案改为“登录你的衣柜”。
- 新页面 `/register`：用户名、昵称（可选）、密码、确认密码、邀请码（`INVITE` 必填，读取 `?invite=` 预填）；成功后直接进入衣柜。
- “我的 → 账户安全”拆为：个人资料（昵称）、修改密码（“同时退出其他设备”默认勾选）、登录设备（当前设备标记、退出其他设备）、注销账号（危险区，模态框输入密码确认）。
- “我的 → 用户管理”（管理员）：用户表格（搜索、状态/角色筛选、分页）、详情抽屉（额度、事件、操作），创建用户与重置密码的结果模态框（临时密码只显示一次，可复制）；“邀请码”标签页：注册模式、创建、复制邀请链接、撤销。
- 顶部与“我的”头像显示昵称首字。
- 全部控件使用 Ant Design Vue。

### 预设库保留名补充（2026-10-21）

`__preset__`（含大小写变体）仅是预设图片的系统存储命名空间，禁止注册、管理员/CLI 创建和登录。账号服务校验、认证提供器与 V32 数据库 CHECK 共同守护，不产生可登录系统用户。详见 [预设衣物库实施记录](2026-10-21-预设衣物库设计.md)。
