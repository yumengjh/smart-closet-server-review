# 对象存储（S3 兼容 · 腾讯云 COS）设计

日期：2026-10-11 · 状态：实现中 · 关联：server issue「图片存储支持 S3 兼容存储桶」

## 1. 要解决的问题

1. **图片慢**：衣物图、基准人物、设计图（试穿/OOTD 渲染）都由后端从本机磁盘读出再发给浏览器，受服务器带宽限制。
2. **磁盘装不下**：图片全部在 `CLOSET_STORAGE_DIR`（容器内 `/data`）里，只会越来越多（衣物删除是软删除，图片不删）。

目标：图片可以放到任意 S3 兼容存储桶（首要是腾讯云 COS），默认仍是本机磁盘（行为与现在完全一样）；提供一条可在本地执行的一键迁移脚本。

## 2. 现状（迁移前的目录）

| 本机路径（相对存储目录） | 内容 | 数据库怎么找到它 |
|---|---|---|
| `workflows/{job}/original.*`、`input.png`、`base-cutout.png`、`step-N.png` | 衣物原图、抠图、贴纸、AI 增强图 | `image_asset(job_id, file_name, sha256, byte_size)` |
| `workflows/{job}/step-N.receipt.json`、`quick-*.json` | 「文件已写、数据库未提交」时的恢复凭据 | 按约定 |
| `batches/{batch}/source-*`、`preview-*`、`reference-*`、`atlas-*`、各类 json | 批量录入的原图、预览、合图、凭据 | `clothing_batch.state_json` 里存文件名 |
| `{seg}/…`、`{seg}/sticker-*/…` | 单独抠图（管理员工具）与贴纸 | `standalone_segmentation_owner` |
| `private-person/{id}.png` | 本人照片、**基准人物**、**设计图/试穿图** | `private_media(id, sha256)` |
| `ootd-samples/{id}.png` | 管理员 OOTD 样本图 | `ootd_sample.image_path`（仅文件名） |
| `db/`、`backups/`、`workflows/.worker.lock`、`private-person/deletion-ledger/` | 数据库、备份、单进程锁、删除墓碑 | — |

关键事实：**数据库里从不保存绝对路径或主机地址**，只保存「任务 ID + 文件名」或 `/api/...` 相对地址。

## 3. 设计

### 3.1 对象键 = 现在的相对路径（数据库零改动）

`workflows/{job}/step-2.png` 在存储桶里的对象键就是 `{prefix}workflows/{job}/step-2.png`。

- 迁移只是「按原路径复制文件」，不改数据库一行，前端拿到的 `/api/...` 地址也完全不变。
- 回滚只需把 `CLOSET_STORAGE_TYPE` 改回 `local`（迁移不删除本机文件）。
- `prefix`（如 `closet/`）可选，便于一个桶放多套环境。

### 3.2 存储抽象 `BlobStore`

```
put(key, bytes, contentType)    get(key) → bytes | null    exists(key)    delete(key)
list(prefix) → [key, size, lastModified]
url(key, ttl) → 预签名直链（本机存储没有）
```

- `LocalBlobStore`：根目录即存储目录；写入保持现在的「临时文件 + fsync + 原子改名」。
- `S3BlobStore`：自己实现 AWS SigV4 签名（`java.net.http`，不引入 AWS SDK）。只用 PUT/GET/HEAD/DELETE/ListObjectsV2 和预签名 GET，COS、MinIO、阿里云 OSS（S3 兼容模式）、AWS S3 都支持。
  - 不引 SDK 的原因：新版 AWS SDK 默认的分块校验和（`aws-chunked` + CRC 尾部）COS 不支持，需要额外关掉；而我们只要五个请求，自己签名代码少、行为可控。签名用 AWS 官方文档的测试向量和 botocore 交叉校验。
  - 对象上写 `x-amz-meta-sha256`，迁移时据此判断「已传过且内容一致」可以跳过。
  - 网络错误和 5xx 自动重试 3 次（指数退避）。
  - 启动时做一次 `ListObjectsV2 max-keys=1` 自检，桶名、地域、密钥错了直接启动失败并给出中文原因，不会等到用户上传才发现。

**留在本机的东西**：数据库、备份、`.worker.lock`（单进程锁是针对本机进程的）、`deletion-ledger`（删除墓碑必须和数据库同处，用于「恢复旧数据库后不复活已删除的私人照片」）、处理中的临时目录。

### 3.3 各模块改造

| 模块 | 改造 |
|---|---|
| `WorkflowFiles` | 用对象键读写；`readVerified` 照旧校验大小和 sha256；`path()` 改为 `key()` |
| `WorkflowService` / `QuickIntakeService` | 「当前图片」从 `Path` 改为对象键；凭据/`quick-*.json` 读写走存储 |
| `SegmentationService` / `StickerService` | 去掉「临时目录整体改名」，改为先写图片、**最后写 `result.json`**（存在 `result.json` 才算完成，语义不变） |
| `BatchService` | 同上，键 `batches/{id}/{file}` |
| `PrivateMedia` | 键 `private-person/{id}.png`；事务回滚删对象；孤儿扫描用 `list`（每小时至多一次）；墓碑仍在本机 |
| `OotdSampleService` | 键 `ootd-samples/{id}.png` |
| 旧版 `job.json` 导入 | 只在本机存储时扫描（旧数据早已导入，S3 模式不再每次启动列举整个桶） |

### 3.4 图片怎么给浏览器：302 跳转到预签名直链

这是「速度慢」的核心解法。鉴权仍在后端做，后端不再传图片字节。

```
浏览器  GET /api/workflows/{id}/files/step-2.png   (带登录 Cookie)
后端    校验归属 → 302 Location: https://{bucket}.cos.ap-guangzhou.myqcloud.com/…?X-Amz-Signature=…
浏览器  直接从 COS 下载图片
```

- **桶保持私有读写**。直链有签名、限时，拿不到别人的图。
- **能被缓存**：签名时间按时间窗取整（默认 1 小时），同一窗口内同一张图的直链完全相同，浏览器缓存可以命中；302 本身带 `Cache-Control: private, max-age=剩余有效期`，二次打开连后端都不用问。
- **私人图片**（本人照片/基准人物/设计图）：窗口 5 分钟、有效 10 分钟，302 响应 `no-store`，与现在的「不缓存」策略一致。
- **画布读取像素的请求走后端转发**：搭配画布需要 `getImageData`，前端用 `crossOrigin='use-credentials'` 加载图片；带凭据的跨域请求被 302 到另一个域名后，浏览器会把 Origin 变成 `null`，COS 无法正确应答。所以**请求头带 `Origin` 时（即 CORS 请求）后端改为直接转发字节**，普通 `<img>` 加载（不带 Origin）才跳转。前端不用改，也不需要给 COS 配 CORS。
- 可配置 `serve: proxy` 让所有图片都由后端转发（存储换到桶里但出口仍走后端，用于排查）。

### 3.5 配置

```
CLOSET_STORAGE_TYPE=local            # local（默认）| s3
CLOSET_STORAGE_S3_ENDPOINT=https://cos.ap-guangzhou.myqcloud.com
CLOSET_STORAGE_S3_REGION=ap-guangzhou
CLOSET_STORAGE_S3_BUCKET=closet-1250000000
CLOSET_STORAGE_S3_ACCESS_KEY=…       # COS SecretId（建议子账号，只授权这个桶）
CLOSET_STORAGE_S3_SECRET_KEY=…       # COS SecretKey
CLOSET_STORAGE_S3_PREFIX=            # 可选，如 closet/
CLOSET_STORAGE_S3_PATH_STYLE=false   # COS 必须 false；MinIO 一般 true
CLOSET_STORAGE_S3_SERVE=redirect     # redirect（默认）| proxy
CLOSET_STORAGE_S3_URL_TTL=1h         # 公共图片直链时间窗
```

COS 要点：桶名带 APPID（`name-1250000000`）；地域写 `ap-guangzhou` 这种；服务器在同地域腾讯云 CVM 上时，默认域名会自动走内网，后端读写不花外网流量。

## 4. 一键迁移

迁移逻辑做成后端自带的命令（`--closet-command=storage-migrate`），复用同一套签名与配置代码；外面包一层本地执行的脚本 `scripts/storage/migrate-to-s3.sh`。

### 4.1 命令的三个步骤

| 步骤 | 做什么 | 需要停服务吗 |
|---|---|---|
| `scan` | 统计要迁移的文件数、总大小，按目录分类；读数据库核对有没有记录了却不存在的文件 | 否（数据库被占用时只统计文件） |
| `copy` | 遍历上表的目录，逐个对象 HEAD：大小与 sha256 一致则跳过，否则上传。并发上传，可反复执行（断点续传） | 否 |
| `verify` | 读数据库，逐条确认 `image_asset`、`private_media`(ACTIVE)、`ootd_sample`、单独抠图在桶里都存在且 sha256 一致；输出缺失清单，有缺失返回非 0 | 是（H2 文件数据库只允许一个进程打开） |
| `pull`（回滚用） | 把桶里本机没有的对象下载回来 | 是 |

### 4.2 脚本流程（在你的电脑上执行，通过 SSH 操作服务器）

```
1. 检查本地 .env.storage（COS 配置）是否齐全
2. 服务器上运行 scan              → 打印要迁移多少文件/多大
3. 服务器上运行 copy（服务不停）  → 大头在这一步，服务器到 COS 直传，不经过你的电脑
4. 确认后：停后端 → 再 copy 一次（只补停服前新增的）→ verify
5. 把 CLOSET_STORAGE_* 写进服务器 .env → 启动后端 → 检查 /api/health
6. 打印回滚方法
```

停服时间只包含第 4、5 步，通常一两分钟。本机文件不删除，确认稳定后可自行清理。也支持 `--local-dir` 模式：在本地对一份已下载的存储目录执行。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 密钥泄漏 | 只放服务器 `.env` 与本地 `.env.storage`（已加入 `.gitignore`），日志不打印密钥；建议子账号最小权限 |
| COS 不可用 | 读写失败返回 503「图片存储暂时不可用」，不会写坏数据库：所有写入都是「先写对象，成功后才提交数据库」，与现在先写文件后提交的顺序一致 |
| 迁移期间有新上传 | 停服后再 `copy` 一次补齐；`verify` 以数据库为准兜底 |
| 想回到本机磁盘 | `pull` 把切换后新增的对象拉回本机，再把类型改回 `local` |
| 后端读图变慢（推荐、向量计算要读图） | 向量、颜色、指纹算一次就存数据库；同地域内网读取延迟个位数毫秒 |

## 6. 不在本次范围

- CDN 加速域名（私有桶 + CDN 需要回源鉴权和 CDN 自己的签名，另做）。
- 自动清理本机旧文件、衣物硬删除时删除图片（现在本来就不删）。

## 决策记录

- **S1** 对象键沿用相对路径，数据库零改动，回滚即切配置。
- **S2** 自签 SigV4，不引 AWS SDK（COS 不支持 SDK 默认的分块校验和；依赖体积）。
- **S3** 普通图片 302 到时间窗取整的预签名直链；CORS 请求（画布）后端转发。
- **S4** 数据库、锁、删除墓碑永远留在本机。
- **S5** 迁移=复制+数据库核对，可重复执行；本机文件不自动删除。
