# 衣物工作台实现与验证 · 2026-10-04

用户已授权按设计实现，并允许实际开发中调整间距、对齐和响应式细节。实现基于当前 25 张多件合图设计，以及原有单件入口本地改动。

## 已实现

- 保留原站侧栏、主题/声音控件、助手与手机导航，未修改 ClosetShell。
- 单件沿用直接提交“识别并整理”的路径，没有增加单件分页核对流程；处理模式说明和边缘建议通过信息图标查看。
- 多件录入保留上传/拍照、智能/补全/标记策略、逐件处理与显式可选合图试用。开启合图后先识别再选择衣物。
- 合图分组从 2 件起，迁移本机保存的 1 件设置；快捷 2/3/4/6 与自定义 2–10，超出批次可处理数量禁用。选择、组数、额度和提交参数同步。
- 选择卡只显示衣物局部缩略图，原图集中在图片图标弹层。后台处理期间显示进度阶段，结果阶段使用紧凑卡片。
- 原有查看详情、对照原图、单件返工、跳过原因、暂停图片恢复、调用用量与未入柜状态均保留。
- 修复可选 fit/thickness/wearingModes 不合规造成整次识别丢失：这些字段降为 UNKNOWN 空值，不伪造建议；核心识别、图片定位及其他严格校验继续执行。
- 修复历史 GARMENT_TARGET_UNCLEAR 永久拦截：有效的新识别可以解除更早的拦截，失败的重识别不能解除未解决拦截；当前明确无衣物/多件/不可用依旧禁止入柜。

## 验证

`npm run build:server` 成功；相关前端测试 10/10，后端 RecognitionWorkflowTest 与 BatchRulesTest 29/29，双方 git diff --check 通过。前端全量为 40/41，失败来自本轮未改动的穿搭摆放测试 outfit.test.ts:57；没有将其报告为本次通过。

Chrome 浏览器插件验证真实批次：4 件每组 4 件=1 次、每组 2/3 件=2 次，自定义上限、模式切换、来源照片弹层、既有结果查看及选择恢复。桌面 3 列等高 128px，结果同行按钮底边相等；390px、320px 无横向溢出。临时 viewport 已复原，未使用 ego-browser。

浏览器仅检查已有数据和界面操作，没有上传照片、生成、返工或确认入柜，没有消耗新 AI 额度。后台处理状态与后端错误恢复由本地模拟模型的集成测试覆盖，本轮没有验证新真实模型输出质量。

已通过构建脚本发布，更新实际运行的 `.local/runtime/smart-closet-workspace.jar` 并重启。JAR 保留原有配置及其他类，静态资源和两处修改类与当前构建逐字节一致；8080 服务与 8091 Agent 健康检查正常，实际 HTTP 返回主 bundle 与发布产物一致。本地 JAR 备份保留，未改用户数据库。未提交或暂存仓库改动，保留原有暂存删除与其他本地工作。
