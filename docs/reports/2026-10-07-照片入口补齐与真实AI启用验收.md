# 照片入口补齐、真实 AI 启用与逐项验收

日期：2026-10-07。状态：已更新实际 8080 服务，8091 助手运行正常。本文是此前“仅本地／模拟验收、人物和 OOTD 用途关闭”状态的后续更新。

本轮发现并修复了真实遗漏：参考照片入口藏在生成弹窗中；全局组件注册漏掉 Upload，上传按钮不能调出文件选择；人物／生成记录／保存搭配列表在读取一行时继续查询，多个页面并发会耗尽四个数据库连接，造成加载超时。此前通过构建和模拟接口测试不足以证明这些页面与真实上游可用。

## 1. 使用入口与本轮修改

- **我的设置 → 个人资料与基准人物 → 参考照片（可选）**：常驻“选择全身照或半身照”按钮，支持 JPG／PNG、20 MB 以内；选择后预览，确认生成才上传。可移除或复用已上传参考。未填写性别仍可选择照片，但不能提交人物生成。
- 生成按钮根据有无新照片显示“上传照片并生成基准人物”或“生成基准人物”。确认页展示真实使用值、默认值来源、照片、模型和一个图像额度。
- 全身照和半身照只参考可见外观；半身照不可见的部分用明确资料或模板补足，不估算真实围度、腿长或身高。不新增识图测量步骤。
- 补齐 Upload、Divider、Badge 注册及追踪弹窗 TabPane 绑定。修复列表查询释放连接后才进行关联读取，增加连接紧张情况下的回归测试。
- OOTD 自动选中可用的已验证模型；参考图中夹带的其他人物、内搭、鞋或装饰不属于所选单品，提示词明确排除。
- 原前端 waiting.ts 的既有并发步骤展示修改保留，未覆盖。未创建提交或推送。

生成人物：保存性别／可选资料 → 可选照片 → 核对并生成单张 → 查看候选 → 确认设为默认人物。

生成 OOTD：先保存组合台搭配 → 进入 OOTD → 选择已确认人物和本次衣物 → 免费检查 → 核对清单／无鞋提示 → 确认单张任务。未保存搭配不能直接生成，基准人物原衣服不能补缺失主体。

## 3. 现有上游真实验收与开放配置

沿用既有 `.local/generation.yml` 的 yumg 配置，没有更换网关或复制密钥到报告。助手／识别使用 gpt-6-luna，人物／OOTD 使用 gpt-image-2.5-flare。

| 样本 | 结果 | 人工核对 |
| --- | --- | --- |
| 男性无照片默认人物 | SUCCEEDED | 单名全身男性、正常基础短袖短裤平底鞋 |
| 女性无照片默认人物 | SUCCEEDED | 单名全身女性、正常基础服饰；确认用于后续 OOTD |
| 合成全身照参考人物 | SUCCEEDED | 可见脸与基本外观延续，正常全身图 |
| 带脸半身照参考人物 | SUCCEEDED | 可见脸／上半身参考延续，下半身按资料模板补足 |
| 人物＋衬衫＋裤子＋外套＋鞋，五参考 | SUCCEEDED | 四件所选物品可辨，只有一件外套，无基准短袖短裤残留，无参考图夹带白 T 恤 |
| 人物＋连衣裙，无鞋，两参考 | SUCCEEDED | 所选条纹连衣裙、赤脚，没有补基准鞋或短裤 |
| 黑白条纹连衣裙识别 | SUCCEEDED／READY | category＝连衣裙，未拆成上下装 |

人物照片样本使用本轮生成的合成人物，未拿用户真实身体照片作测试；上述结果不能证明任意本人照片的身份相似度。不同纹理、条纹和脸部细节仍可能变化，结果需用户核对。

实际图像请求共 **7 次生成＋1 次识别**：5 次人物生成、2 次 OOTD、1 次识别。人物样本准备时有一张局部裁切未带脸且已派发，该次成功但不计作带脸半身照片的相似度证据；另一次错误裁切任务在派发前取消，未请求上游。不自动重新生图，也不循环刷图。全部在隔离 QA 账号／数据库验证，没有向真实账号加入测试衣物、照片或人物。

真实助手共 8 个用户请求：问候、数量、多品类数量、否定搭配、三套推荐、修改、能力咨询及修改复验。第一次修改请求遇到上游 HTTP/2 stream failed，未执行写操作；随后明确重新发起的修改验证成功并完成撤销。不能据此声称上游每次都成功。

生产已登记并启用：

| 用途 | 模型 | 参考上限 | 输出 |
| --- | --- | --- | --- |
| BASELINE | yumg / gpt-image-2.5-flare | 1 张可选照片 | 1024×1536、low、PNG、单张 |
| OOTD | yumg / gpt-image-2.5-flare | 5 张，包含基准人物 | 1024×1536、low、PNG、单张 |

上限是本次实测开放范围。超出上限会明确阻止，不默默丢衣物或自动拼图。供应商参数改变后旧验证失效，需要重新核对。原识别、衣物生图与任务配置保留；没有解除确认、每日额度或隐私权限。
