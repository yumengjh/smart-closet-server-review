# 智能搭配低级错误：诊断与修复

日期：2026-10-03

## 结论

本地衣柜有 21 件 ACTIVE 衣物，全部有有效品类，包含上装、裤装、连衣裙、开衫及外套。不能把用户报告的错误直接归因于缺少元信息。当前实现最明确的问题是：组合工具只验证归属、状态、重复与指定衣物，没有验证穿着结构。

同时发现：

- 原提示词没有上装/下装/连体主体、外搭数量和内外层级规则。
- Agent 只收到少量属性值，没有识别状态、证据、用户修改来源；门襟字段未传入，画板已有衣物只有 ID 和几何信息。
- 前端将开衫识别为普通上装，将包含“西装”的裤装误分到外套；带帽卫衣可能匹配帽子。错误角色会影响布局和绘制层级。
- 模型推理强度固定为 `none`。现调整为 `low`，但未做控制变量对比，不能断言推理强度是主要原因。
- 检索只有连续子串语义：独立查询 T恤可找到 2 件、长裤可找到 4 件，而查询 `T恤 长裤` 返回 0。真实画布测试也发现模型错误声称这两类衣物不存在；没有保存该轮工具参数，不能确定它实际使用的检索词。

## 已实施

1. 默认基础组合为一件上装加一件下装，或一件连衣裙/连体衣；可选一件外搭和鞋、帽、包、配饰。重复主体、双外搭、连衣裙混上装/下装、没有主体或角色不明的方案会在创建画板/预览前拒绝，并返回具体修正原因。
2. 编辑工具按操作后的最终组合检查冲突；传统预览确认时重新读取有效品类。支持删除主体后的不完整编辑，不把手工拼贴编辑器限制成基础穿搭工具。
3. 补充 `wearing.role/layer`、元信息来源/状态/证据、门襟和当前画板真实衣物资料。角色由有效品类推导，不伪称知道厚度、版型或叠穿适配性。
4. 修正上述分类；AI 添加、替换或移除衣物后按穿着角色整理绘制层级，保留位置和尺寸。外搭绘制在上装/连衣裙之上，传统预览与临时搭台一致。
5. 增加基础穿着规则、库存不足处理、校验失败修正和证据使用规则；推理强度调整为 `low`。
6. 明确检索契约。关键词零命中时工具回退未筛选衣柜第一页，返回 `matchedTotal/fallbackApplied/appliedQuery/hasMore` 及核查说明；模型优先浏览全部库存，核查分页后才能断言缺少某类衣物。覆盖零命中和错误页码回退的接口测试。

这些规则只保证默认基础组合的穿着结构。衬衫配吊带裙、多层外搭、衬衫叠毛衣等特殊叠穿存在合理情况，当前基础工具暂不支持，不能把默认限制理解为通用服装定律。要可靠支持这些情况，还需明确内外搭角色、版型、厚度、袖型及用户叠穿意图。此次没有修改已有衣物元信息或批量重跑识别，也没有对审美质量作保证。

- Agent 运行时：12 项测试全部通过，包含工具拒绝后将具体原因返回模型、继续修正提交。运行时构建通过。
- 前端：新增角色与层级测试通过；全量 37 项中 36 项通过。原有“新衣物初始位置”测试失败，在未修改的 HEAD 源码副本中复现同一断言失败，与本次改动无关。
- 前端类型检查和 `npm run build:server` 发布通过，服务端打包通过。
- 真实模型 `gpt-6-luna`：普通三套和指定连衣裙三套均返回合法组合；库存无主体、品类未知均说明限制并不生成。四场景没有提出被校验拒绝的组合。该验证使用合成元信息和测试执行回执，不等同于画布端到端测试。
- 本地服务更新前备份数据和旧版本，确认无处理任务、批次或活跃 Agent 会话；更新后后端、助手健康和实际提供的前端入口均已核验。
