3. 记忆：原始 Markdown、并发 revision、敏感用途授权、片段输入与授权撤销、上下文 epoch、旧事件回灌和流式运行的失效检查。
4. 搭配：场景与实际穿法分离、同一衣物去重、连体覆盖、外套限制、受限多层、首饰位置、全身分布和多套选择；生成准备再次验证已保存版本。

## 审查发现与修正

| 编号 | 问题及影响 | 修正与验证 |
|---|---|---|
| R1 | 个人图片执行器在数据库行映射中加载冻结输入，可能嵌套借用连接；小连接池和并发列表请求会放大等待。 | 先完成任务 ID／账号查询并释放连接，再读取冻结输入。连接池回归占用三个连接，在余下一个连接下验证个人列表及任务候选。 |
| R2 | 敏感记忆读取分开检查版本、用途许可和正文，并发编辑可能在检查后替换正文。 | 在短事务中锁定账号，统一读取授权与文档快照；并发测试证明编辑等待快照完成，当前请求不读新正文，随后新版本授权失效。 |
| R3 | Agent 在读取输入之后才记录上下文 epoch，准备与流式派发之间撤销记忆时可能仍派发旧输入。 | 先记录 epoch，派发前复验，工具及流式结果继续复验。新增测试在准备后撤销，断言运行时收到零次请求。已发送到上游的输入无法撤回。 |
| R4 | 单件资料撤销的条件更新未检查受影响行数，竞争更新时存在错误标记为撤销成功的可能。 | BASIC／METADATA 撤销检查条件更新结果，不命中即冲突并回滚；保留既有对象版本与撤销回归。 |
| R5 | OOTD 确认弹窗中的失败只显示在弹窗后方；提交响应丢失时没有核对原任务。 | 在确认弹窗内显示错误，立即进入提交状态；不确定响应查询原幂等提交，找到原任务则关闭弹窗并刷新记录，没有自动重复 POST。重试保留原提交键。浏览器故障夹具覆盖丢响应恢复和明确 409 拒绝。 |

基准人物上传的加载状态、60 秒上传期限、10 秒原提交查询、冻结文件与参数、结果未知时防重复、私有照片列表连接占用等前序修复也包含在本次功能提交中，详见对应报告。

- 原提交键未跨刷新持久恢复；连接不确定时保留当前窗口并核对生成记录，不能关闭后盲目新建任务。
- 照片、人物、OOTD 独立删除已提供；一键关联清除入口、OOTD 卡片完整历史来源与人物版本展示仍需完善。
