# 衣物录入体验修复

## 主流程

入口统一为选照片 → 自动整理 → 核对入柜。所有新录入照片使用多目标识别，单件照自然返回一件，多件同框与自拍无需选择通道。默认筛选细节清楚的目标；遮挡补全、手动指定目标放在可选设置。历史批次保留原有通道与策略。

手机主按钮紧接照片预览，说明与可选设置放在其后，减少寻找下一步的滚动。

普通录入移除合图、模型、分辨率、质量与调用明细选择。仍按逐件生成、1024参考、标准质量处理；原图保留。合图试验能力留在接口中，质量与20%成本门槛未取得新结论，默认不启用。

## 卡住问题

原入口将试验预算保护用于普通整理，识别账单字段缺失时会阻止合图继续；浏览器内存中的自动整理意图在刷新后丢失。

新增 `/api/closet/batches/{id}/start`：先保存完整处理意图及整理模型配置版本，再入队识别。识别结束后由服务端提交逐件整理，浏览器关闭不影响衔接。识别金额未知不再影响普通流程；试验脚本仍遵守预算暂停规则。配置版本改变或额度不足时保留结果，明确提供人工继续入口。不会自动重放失败或结果未知的调用。

额度不够完成全部目标时，前端提供“先整理 N 件”，也可以指定单件。额度为零、配置缺失、无标记等情况有原因及下一步。生成后的 NEEDS_REVIEW 状态仍能进入原有单件核对页，避免有图无入口。失败只影响对应衣物，已保存生成图可继续本地处理。

## 验证

- 42项后端测试通过，包括新增的无浏览器衔接、费用未知继续、重复提交、额度不足保留结果与单件继续；既有图像方向、筛选、工作流与API测试通过。
- 2项前端筛选/标记规则测试通过；前端类型检查、生产构建及 build:server 发布通过。
- 实际浏览器390px：选择两张照片（含24MP EXIF旋转照片）、真实上传原图、手动标记、刷新恢复、按钮可用；无水平溢出，无可见原生select。
- 实际已识别且金额未知的历史批次：继续整理按钮可用，没有合图选项。
- 浏览器拦截生成请求验证界面：提交两个实际目标、逐件生成参数；处理中→部分结果需要核对/部分失败；对照原图；仅余1额度时先整理1件，零额度时说明明日继续。拦截部分为模拟结果，不代表真实模型质量验收。
