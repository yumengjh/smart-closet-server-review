# 从识别资料与候选筛选源头降低搭配错误

## 已实现

识别协议升级为 garment-v4，在原有单次识别里加入 fit（版型建议）、thickness（厚薄线索）、wearingModes（穿着用途建议）。这些照片结果只允许 INFERRED 或未知/不适用/冲突，不将视觉猜测当作实物事实；已有属性仍保留 OBSERVED 与 INFERRED 的区别。自动结果保存状态、依据、提示词哈希和协议版本。

旧识别结果兼容读取，新字段缺失时返回空值，保留其他元信息和图片。衣物详情可手动补充三项资料，显示来源和依据，提供「我已根据实物核对三项穿着资料」按钮：即使值与自动建议相同，也可以保存为用户覆盖值；恢复自动值会撤回确认。未自动批量重识别旧衣物，未因搭配查询产生识别调用。

新增 get_outfit_candidates：后端读取本人已入柜衣物，在模型选择之前生成最多 40 个确定性的结构合法候选（扫描上限 1000 件，返回截断状态）。支持必选 ID 与页面指定衣物，返回候选 ID 和去重衣物资料。模型只通过 candidateId 选择，新建工具不再开放任意 garmentIds 拼接。本轮候选 ID 只在当前运行有效；执行前仍检查所有权、实时资料和规则。候选池是有限集合，不是审美排名，也不代表全部库存。

规则 daily-evidence-v3：单层主体可直接参与候选；只有内外两件三项资料均由用户确认、内件可作内搭且修身/合体、厚薄为薄/常规、外件可作外搭且宽松、厚薄等级不小于内件，才进入保守叠穿候选。该规则不保证实际尺寸松量、人体适配或审美。其他重复穿着位置、连衣裙与上/下装互斥等规则继续生效。未知不会引发模型去付费重新识别。

候选返回精简质量状态，完整依据通过 get_garment 按需查看；校验 trace 仍保存实际选中衣物的完整资料与来源，减少重复证据进入模型上下文。

## 升级保护

回归发现 WorkflowService 与 RecognitionService 将需明确衣物目标的协议写死为 garment-v3，新协议会漏掉识别失败后的生图停止规则。本轮统一 requiresTarget 判断，兼容旧 v3 与当前 v4；识别失败时不会继续花费预设整理的生图调用。此问题在升级中被测试发现，修复后再发布。

## 验证与边界

后端相关 34 项通过（候选 2、规则 6、API 11、识别工作流 15），runtime 14 项通过，前端类型检查/发布通过。前端测试 41 项中 40 项通过，已有初始水平间距断言失败。服务更新前确认没有活动任务并备份数据库；服务及助手健康检查通过。

本轮未进行付费真实照片识别对比，因此新增视觉建议质量尚未实测，不能声称照片能可靠识别实物厚度。历史衣物的 AI 批量补全尚未实施；可以免费手动补充并核对，也可由用户主动执行已有「重新识别信息」。候选目前解决结构与保守叠穿资格，场景、配色及审美仍由模型排序，不能保证方案质量全面改善。
